# Host HITL bridge (CW-20261001-0488)

Tachyon validates plugin `status=ask` responses and optionally enqueues them through Tangent's supported Streamable HTTP MCP caller API. Tangent owns interactions and participant decisions. The host uses released `go-hitl v0.1.0` typed retrieval and terminal outcomes, and MCP SDK v1.8.0.

`TACHYON_TANGENT_MCP_URL` defaults to unset: the plugin response is returned **byte for byte unchanged**, including unknown fields and malformed asks; no bridge validation, handle additions, or network requests occur. Set it to an operator-approved Tangent `/mcp` URL to enable enqueue/get/await. This URL is unrestricted operator configuration, never browser-supplied; startup logs its scheme and host only, excluding path/query/credentials. `TACHYON_TANGENT_ITEM_BASE` is a separately approved HTTP(S) operator link origin. If unset no item link is exposed. Returned links must match that origin and the exact `/hitl/items/{item_id}` path; unrelated origins, credentials, queries, fragments, and unsafe schemes are rejected. Configuration is validated before loading children.

Configured successful asks retain status/prompt/options/context and add `operation_id`, `item_id`, `item_url` when safe, `state`, `expiry`, and `continuation:"unavailable"`. Failed enqueue retains an unavailable ask, never approval, releases the correlation slot, and omits operation_id/expiry. Plugin-supplied host handles are discarded. Asks require a nonblank prompt of at most 4000 Unicode characters, approval or attention kind (approval by default), valid future expiry, and no simultaneous data/error. Summary is shortened to600 characters and the host title to160; approval impact fields are limited to2000 each. Attention with impact is rejected. Exact outgoing bytes and fake MCP enqueue requests are validated against the vendored Tangent request schema in tests (provenance in internal/hitl/testdata/README.md).

POST `/api/verb/{verb}` now reads chunked bodies as well as fixed-length bodies. It caps ingress at1MiB, rejects trailing garbage or multiple JSON values with400, and maps body read errors (including the ingress limit) to413. Dispatch still occurs once. For asks, the bridge checks the32KiB payload byte cap **before JSON decoding**, then checks the canonical payload and serialized enqueue caps. Larger asks remain unavailable without enqueue. These ingress behaviors apply even when the bridge is unconfigured; the plugin's resulting response remains untouched in that mode. POST origin hardening is outside this PR (the Vite proxy needs a separate policy).

Correlation exists only in host memory, capped at256 entries and10 minutes (shortened by ask expiry). No existing entry is evicted to admit a new one. Pruning is lazy at admission/status lookup; unused expired entries may remain allocated until the next lookup, within the256-entry bound. Each entry retains only kind, exact frozen enqueue snapshot (up to32KiB), safe handle, expiry, process identity callback, and one poll semaphore; it does not retain a second request object or caller context. Restart, dead plugin, TTL, capacity, or missing correlation fails closed. Host binding is five supported `correlations.additional` references (`kind:"other"`, `authority:"tachyon"`): epoch, operation ID, exact process generation, verb, and lossless canonical payload SHA-256. Plugin correlations are dropped so they cannot spoof host references or consume Tangent's16-entry allowance.

Each initial invocation creates a distinct operation, even with identical verb/payload. The enqueue key is scoped to host epoch, operation ID, and ask generation. A lost enqueue response permits one bounded retry of the identical frozen request/key; it never dispatches the plugin again. Repeating POST `/api/verb` is a new invocation, not an idempotent write retry. Enqueue/status failures log only a reason class and an opaque operation ID prefix, excluding URL, payload, provider error text, or secrets. Tangent items orphaned by a lost response, expired correlation, process replacement, or host restart remain Tangent-owned and expire at the supplied deadline; Tachyon does not withdraw or resolve them.

`GET /api/hitl/operations/{operation_id}` is read-only and returns a safe status projection: operation/item IDs, state, expiry, approved, decision/resolved_at when terminal resolved, and `continuation:"unavailable"`. It never exposes terminal_outcome, participant/proof, resolution IDs, notes/replies, provider failure messages, or extra fields. Optional `wait_ms` is0..25000 (default0=get); positive uses await. One backend poll per operation is permitted; parallel callers receive503 `poll_busy`, with no additional MCP session. Each tool call, including initialization/cleanup, has a host budget:10s enqueue/get; enqueue retry shares20s; status await wait+5s, at most30s (the underlying client can support Tangent's50s maximum with55s). Responses are capped at256KiB. Status uses no-store and rejects explicit foreign Origin and same-site/cross-site browser requests. Missing Origin remains available to local clients; this adds no authentication.

The host validates request snapshot, item ID, revisions, contract version, lifecycle state, typed terminal identity and kind-specific decision, then checks correlation again after waiting. `approved:true` means terminal `resolved` with response `{kind:"approval",decision:"approved"}` for an approval item. Attention, denial, canceled, expired, failed, superseded, malformed/forged status, and lookup failure never approve. Missing correlation returns410; backend/validation failure returns502 with approved false. Await timeout does not cancel Tangent's item.

**Continuation is unavailable.** There is no POST/resume route, no automatic verb replay after approval, and no provider call from status. Unknown write completion remains unknown. The current plugin carrier cannot safely express a trusted continuation; CW-20261001-0532 holds that design decision. Frontend pending treatment is a separate half of0488, gated on design-kit0039. This host change is not a complete HITL continuation runtime.
